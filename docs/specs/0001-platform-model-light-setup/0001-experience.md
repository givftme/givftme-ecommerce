# Experience contract

## Summary

The person sees useful suggestions before making an account or configuring reminders. Every transition preserves their context and clearly distinguishes a draft, a saved date, and an active reminder. Existing pages and components provide the base; new UI is limited to the missing experiences below.

## Journey and entry points

1. Direct `/dates`, site navigation, or a Create/save a date action opens public discovery for a visitor and the Dates dashboard for an authenticated user. A valid restored draft takes precedence over an empty dashboard, but never silently overwrites another open draft.
2. Cold landing `/` adds a guided relationship then date/occasion entry requesting a target of six ideas after fallback. The existing store remains accessible. Carry relationship, occasion, and selected gift through product navigation and an optional Save this date action. Keep the distinct requested counts for Dates and cold discovery; either may truthfully show fewer or zero valid ideas.
3. A shared wishlist visitor continues viewing and gifting without signup. An optional save/remind action after gift selection or completion may enter this flow. Preserve authorized shared context through the protected temporary capability service, rechecking permissions after auth and at every item action. Expired/revoked access shows an unavailable state and generic ideas without blocking save. Only seed information that the viewer was entitled to see; never copy private addresses, giver identity, or claim state into a draft.
4. The first Dates form uses name, relationship, and date. It says When is their birthday? with Different occasion. Birthday day/month are sufficient; Add birth year is optional. Changing the occasion updates date semantics and copy without discarding the name or relationship. For a managed movable occasion, the date field shows the regional occurrence or Date awaiting confirmation rather than demanding an invented date. Unresolved managed occasions remain saveable.
5. Completing the three fields immediately requests a target of three ideas. After fallback, show the available suitable results, including zero, without inventing or repeating items. Choose a gift, edit details, explore more gifts, or save the date. Suggestions never require interests, budget, full profile, or notification setup.
6. Save date requests authentication only when necessary. Explain that signing in saves the date and lets the user choose reminders. Preserve the full minimal draft. A successful corresponding auth continuation completes only its immutable operation and frozen draft revision for the verified User, if valid and conflict free; a later rediscovered draft is restored for review with Save date.
7. Save success retains the suggestions and offers minimal reminder enablement, Add another person, and Skip for now. A consented selection establishes the user's default. New import entry appears only after this successful manual save. Reminder setup failure does not undo the date save. Visibly confirm a detected valid IANA timezone or let the user choose one; without confirmation, show timezone setup required and keep external reminders inactive. Skipping remains available.
8. Returning users see dates, people with no dates, history, and reminder status. Editing one occasion does not unexpectedly edit person details shared by other occasions. Editing a Contact's relationship is explicitly person level.
9. Account navigation opens `/account` as a hub with Profile, Orders, Notifications/Reminders, and Security destinations. Each nested screen offers a clear return to Account. An occasion's reminder settings link directly to `/account/notifications` and retain a safe return to the originating occasion. Existing `/account/orders/[id]` links continue to open the same authorized order detail.
10. Sign out remains an account action with pending, failure/retry, and successful signed out states, not a separate route. No account hub, Profile, Security, menu, or other account surface exposes Delete Account, its confirmation dialog, or a destructive account section in this release. Person and Occasion deletion remain available only under their separate Dates contract.

### Universal behavior

Use one responsive component per concept and the existing UI registry as the design baseline. Mobile sheets fit the available viewport and scroll above the keyboard; primary actions stay reachable without covering errors. Date selection must not force scrolling through years to enter an unknown birth year. Phone entry supports international prefixes; code input accepts paste and platform autofill without forcing a custom keypad.

Every async action has a text status and prevents accidental repeated submission while retaining retry after failure. Announce save, import, validation, and reminder outcomes accessibly. Label every field, keep focus visible, return focus after dialogs, focus the first invalid field, and support keyboard selection in contact suggestions. Do not rely on color or animation alone. Respect reduced motion.

Retain entered data on network failure. After an ambiguous write outcome, reconcile with the same operation key before offering a fresh save. Browsing and date editing remain available when recommendations fail. Offline edits remain provisional in tab memory; reconnect requires revision reconciliation before replacing server draft state or saving. Persistence requires connectivity and must never be falsely reported as saved. Images have stable placeholders and meaningful alternatives; text and actions work before image loading completes.

Public discovery serves useful HTML and does not require a heavy animation bundle. Private screens and draft responses are not shared cache entries or indexed pages. Metadata and URLs contain no person's name, birthday, phone, tokens, or draft body. Test at 360 CSS pixels and with a keyboard and screen reader; use a midrange Android device under throttled 3G. The product's under three second public wishlist target belongs to feature 3 and remains a dependency, not evidence of this feature's performance.

### Condolence

Selecting condolence changes the complete journey context, including results, save success, reminder setup, date cards, and any surrounding banners. Suppress mascot, confetti, celebratory badges, streaks, urgency pressure, and celebratory fallback artwork. Use quiet functional status text and suitable curated items. A generic celebratory collection is not an acceptable last fallback. Do not automatically recur a condolence event. Final muted palette and typography treatment require design review, not invented tokens in this spec.

## Rationale

This reuses functioning forms, catalog cards, and auth shells while changing the sequence that currently hides value behind authentication. Screen states explicitly separate saving, permissions, and delivery so backend capability cannot silently change the promised experience. Governing sources and session attribution are in `rationale.md`.
